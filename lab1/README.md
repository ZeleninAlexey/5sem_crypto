DES и DEAL реализованы; пункты 5 и 7 демонстрируются отдельными функциями в [lab1.cpp](lab1/lab1.cpp).
После setKey методы блочного шифра должны поддерживать параллельные вызовы без изменения состояния.
Контекст принимает владение алгоритмом через std::unique_ptr<IBlockCipher>, размер блока — от 1 до 255 байтов.

## Использование

```cpp
#include "lab1/CryptoContext.h"

void example(std::unique_ptr<crypto::IBlockCipher> cipher,
             const crypto::Bytes& key, const crypto::Bytes& iv)
{
    crypto::CryptoContext context(key, crypto::CipherMode::CBC,
        crypto::PaddingMode::PKCS7, std::move(cipher), iv, crypto::WorkerCount{4});
    crypto::Bytes source = {1, 2, 3, 0};
    auto encrypted = context.encryptAsync(source).get();
    crypto::Bytes restored;
    context.decryptAsync(encrypted, restored).get();
    context.encryptAsync(std::filesystem::path("input.bin"),
        std::filesystem::path("encrypted.bin")).get();
    context.decryptAsync(std::filesystem::path("encrypted.bin"),
        std::filesystem::path("restored.bin")).get();
}
```

Все операции запускаются через std::async(std::launch::async); future.get() ожидает результат и передаёт исключения.
Выходной массив в перегрузке по ссылке должен жить и не использоваться до завершения операции.
Входной массив копируется или перемещается в задачу; сам контекст можно уничтожить до её завершения.
Каждая операция начинает работу с исходного IV; для независимого сообщения нужно использовать новый IV.
IV, Delta и исходная длина передаются отдельно и не записываются в шифротекст.

## Режимы и дополнительные параметры

Поддерживаются ECB, CBC, PCBC, CFB с полным блоком обратной связи, OFB, CTR и RandomDelta.
IV должен иметь размер блока; для ECB он должен быть пустым.
CTR использует IV как начальный big-endian счётчик с шагом 1 и сложением по модулю 2^(8 * размер блока).

В задании не указана формула Random Delta, поэтому принята явная конвенция:
```text
M_i = IV + i * Delta (mod 2^(8 * blockSize)), i начинается с 0
C_i = EncryptBlock(P_i XOR M_i)
P_i = DecryptBlock(C_i) XOR M_i
```
Delta передаётся дополнительным аргументом crypto::Delta{bytes}, имеет размер блока и нечётное big-endian значение.
Случайные IV и Delta подготавливает вызывающий код; их нельзя повторно использовать для независимых сообщений.
Если в курсе определён другой формат RD, эту конвенцию потребуется согласовать с ним.

Параллельны ECB, CTR, RandomDelta в обе стороны; CBC и CFB при дешифровании.
Остальные преобразования последовательны из-за зависимости между блоками.
crypto::WorkerCount{n}: от 1 до 64 задач, по умолчанию до 8 аппаратных потоков.

## Набивки

PKCS7, ANSI X.923 и ISO 10126 добавляют от 1 до blockSize байтов, включая полный блок для выровненного входа.
ISO 10126 получает случайные байты из std::random_device, последний байт содержит длину набивки.
Zeros дополняет только неполный блок; пустой и выровненный вход не расширяются.
Для дешифрования Zeros обязателен аргумент crypto::OriginalSize{исходная_длина}, иначе реальные нули в конце
невозможно отличить от набивки; длина и нулевые байты проверяются.

## Файлы

Обработка выполняется порциями по 1024 блока с сохранением состояния режима; файл целиком не загружается в память.
Набивка обрабатывается только в последней порции. Один файл нельзя использовать как вход и выход.
Выходной файл перезаписывается и при ошибке может содержать частичный результат.
Проверка набивки не является проверкой подлинности шифротекста.

## Пункт 3: сеть Фейстеля

[FeistelNetwork](lab1/FeistelNetwork.h) реализует IBlockCipher и принимает размер блока
в байтах, std::unique_ptr<IKeyExpansion> и std::unique_ptr<IRoundFunction>.
Размер блока должен быть положительным и чётным; число раундов равно числу сгенерированных ключей.
Вызов setKey обязателен до обработки блока и не должен выполняться параллельно с обработкой.
Раунд: L_next = R, R_next = L XOR F(R, K). Выход сети: R_n || L_n.
При дешифровании применяется та же процедура с обратным порядком раундовых ключей.
Функция F возвращает ровно половину блока; она не обязана быть обратимой.
Начальная и конечная перестановки DES относятся к следующему пункту и выполняются вне сети.
Реализация F должна поддерживать одновременные вызовы; промежуточные половины блока локальны.
[FeistelTests.cpp](tests/FeistelTests.cpp): успешно проверены 3072 восстановления блоков,
ручные векторы для 1–3 раундов, ошибочные параметры и параллельная работа через CryptoContext.

## Пункт 4: DES

[DesCipher](lab1/DesCipher.h) реализует IBlockCipher и использует FeistelNetwork с
[DesKeyExpansion](lab1/DesKeyExpansion.h) и [DesRoundFunction](lab1/DesRoundFunction.h).
Таблицы и преобразования соответствуют [FIPS 46-3](https://csrc.nist.gov/files/pubs/fips/46-3/final/docs/fips46-3.pdf).
IP, обратная IP, PC-1, PC-2, расширение E и перестановка P используют permuteBits из пункта 1.

Блок и исходный ключ имеют размер 8 байтов. PC-1 отбрасывает 8 битов чётности ключа;
их значения не проверяются и не влияют на шифрование. Из оставшихся 56 битов создаются
16 раундовых ключей по 48 битов с циклическими сдвигами двух 28-битных половин.
Раундовая функция: расширение 32 → 48, XOR с ключом, восемь S-блоков 6 → 4, перестановка P.
Перед сетью выполняется IP, после сети — обратная IP; дешифрование использует обратный порядок ключей.

```cpp
#include "lab1/DesCipher.h"

crypto::DesCipher des;
des.setKey({0x13,0x34,0x57,0x79,0x9B,0xBC,0xDF,0xF1});
auto cipher = des.encryptBlock({0x01,0x23,0x45,0x67,0x89,0xAB,0xCD,0xEF});
// cipher = 85 E8 13 54 0F 0A B4 05
auto plain = des.decryptBlock(cipher);
```

Для работы с массивами и файлами передайте std::make_unique<crypto::DesCipher>() в CryptoContext.
Вызов setKey не должен выполняться параллельно с преобразованием блоков.
[DesTests.cpp](tests/DesTests.cpp) успешно проверяет пять известных векторов в обе стороны,
первый и последний раундовые ключи, значение раундовой функции, независимость от битов чётности,
256 восстановлений с разными ключами, ошибки размеров и 196 сочетаний режима, набивки и размера данных.
Компиляция MSVC выполнена с /std:c++20 /W4 /WX.

## Реализация DEAL, пункт 6

- [DealCipher](../lab1/DealCipher.h) реализует IBlockCipher, блок 16 байтов, на основе общей FeistelNetwork.
- [DealKeyExpansion](../lab1/DealKeyExpansion.h) реализует генерацию раундовых ключей.
- [DesRoundAdapter](../lab1/DesRoundAdapter.h) адаптирует полное шифрование DES к IRoundFunction.
- Реализация: [DealCipher.cpp](../lab1/DealCipher.cpp).

| Исходный ключ | Частей по 8 байтов | Раундов | Раундовый ключ |
|---|---:|---:|---:|
| 16 байтов / 128 бит | 2 | 6 | 8 байтов |
| 24 байта / 192 бита | 3 | 6 | 8 байтов |
| 32 байта / 256 бит | 4 | 8 | 8 байтов |

F(block, roundKey) — полное шифрование DES. Адаптер создаёт локальный DES, поэтому параллельные вызовы не меняют общий ключ. Этот простой вариант заново генерирует подключи DES при каждом вызове F.

### Расписание ключей

В DealKeyExpansion каждый раундовый ключ вычисляется явно: для ключей 128 и 192 бита записаны по 6 вычислений, для 256 бит — 8; цикла генерации нет.

Ключ делится на части K_0 ... K_(s-1) по 8 байтов. Применяется собственный DES с фиксированным ключом 01 23 45 67 89 AB CD EF, без набивки.

```text
R_(-1) = 0
R_i = DES_fixed(K_(i mod s) XOR R_(i-1) XOR Q_i)
Q_i = 0                           при i < s
Q_i = 0x8000000000000000 >> (i-s)  при i >= s
```

Маски повторного прохода: 80 00 ... 00, 40 00 ... 00, 20 00 ... 00, 10 00 ... 00; для ключа 192 бита нужны только первые три. Исходные части поступают в DES как данные, их младшие биты не отбрасываются. Биты чётности исключаются только при использовании полученных R_i как ключей DES.

### Порядок половин

Выбрана запись с воздействием первого раунда на правую половину:

```text
L, R = половины входа
раунд 0: R = R XOR DES_R0(L)
раунд 1: L = L XOR DES_R1(R)
раунд 2: R = R XOR DES_R2(L)
...
выход: L || R после последнего раунда
```

Общая FeistelNetwork подаёт в F правую половину и возвращает R_n || L_n. DealCipher согласует порядок при чётном числе раундов: меняет половины перед шифрованием сетью и после дешифрования сетью. Перестановки DES уже включены в адаптер; отдельных IP/FP над 128-битным блоком нет.

Описание алгоритма: [S. Lucks, On the Security of the 128-Bit Block Cipher DEAL](https://citeseerx.ist.psu.edu/document?doi=2c417e66b47e36c7b723715609fc76980c48b04c&repid=rep1&type=pdf), [J. Kelsey и B. Schneier, Key-Schedule Cryptanalysis of DEAL](https://www.schneier.com/wp-content/uploads/2016/02/paper-deal.pdf). В записях порядок половин может отличаться; реализованная конвенция указана выше.
