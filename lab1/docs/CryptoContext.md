# Работа CryptoContext

Контекст объединяет блочный алгоритм, ключ, режим шифрования и набивку. Он принимает массив байтов или файл произвольного размера, разбивает данные на блоки и возвращает результат асинхронно. Для DES размер блока равен 8 байтам (64 битам).

Исходный код: [объявление](../lab1/CryptoContext.h), [реализация](../lab1/CryptoContext.cpp), [пример запуска](../lab1/lab1.cpp).

## 1. Создание контекста

```cpp
CryptoContext(key, mode, padding, cipher, iv, дополнительные_аргументы...)
```

| Параметр | Значение |
|---|---|
| `key` | Массив байтов ключа; требования к длине определяет алгоритм, DES принимает 8 байтов |
| `mode` | Значение `CipherMode`: ECB, CBC, PCBC, CFB, OFB, CTR или RandomDelta |
| `padding` | Значение `PaddingMode`: Zeros, AnsiX923, PKCS7 или Iso10126 |
| `cipher` | `std::unique_ptr<IBlockCipher>` с конкретным алгоритмом |
| `iv` | Начальный вектор размером в блок; для ECB — пустой массив, который можно не указывать |
| Дополнительные аргументы | `WorkerCount`, `OriginalSize`, `Delta`, в произвольном порядке без повторов одного типа |

Конструктор проверяет параметры, вызывает `cipher->setKey(key)`, получает размер блока и сохраняет настройки. Генерация раундовых ключей происходит внутри алгоритма при `setKey`, а не для каждого блока. Поддерживаются размеры блока от 1 до 255 байтов.

`std::make_unique<crypto::DesCipher>()` создаёт DES и передаёт контексту владение им: контекст управляет временем жизни алгоритма. Если алгоритм уже находится в переменной `std::unique_ptr`, передайте её через `std::move`.

## 2. Полный пример для массива

```cpp
#include "CryptoContext.h"
#include "DesCipher.h"
#include <exception>
#include <iostream>
#include <memory>

int main()
{
    try
    {
        const crypto::Bytes input = {0x01, 0x02, 0x03, 0x04, 0x05};
        const crypto::Bytes key = {0x13, 0x34, 0x57, 0x79, 0x9B, 0xBC, 0xDF, 0xF1};
        const crypto::Bytes iv = {0x01, 0x23, 0x45, 0x67, 0x89, 0xAB, 0xCD, 0xEF};

        crypto::CryptoContext context(key, crypto::CipherMode::CBC,
            crypto::PaddingMode::PKCS7, std::make_unique<crypto::DesCipher>(), iv);

        auto encryption = context.encryptAsync(input);
        // Здесь можно выполнять другую работу, пока идёт шифрование.
        const auto encrypted = encryption.get();
        const auto decrypted = context.decryptAsync(encrypted).get();

        std::cout << "Encrypted bytes: " << encrypted.size() << '\n';
        std::cout << "Restored: " << (input == decrypted) << '\n';
        return input == decrypted ? 0 : 1;
    }
    catch (const std::exception& error)
    {
        std::cerr << error.what() << '\n';
        return 1;
    }
}
```

Здесь зашифрованный массив содержит 8 байтов, а восстановленный — исходные 5. IV зафиксирован для воспроизводимости примера; контекст сам не генерирует новый IV.

## 3. Путь данных внутри контекста

```text
encryptAsync / decryptAsync
    → запуск фоновой задачи с сохранёнными настройками
    → process (массив) либо processFile (файл)
    → processStream: чтение порции
    → pad: только для последней порции при шифровании
    → Session::transform: обработка блоков выбранным режимом
    → unpad: только для последней порции при дешифровании
    → запись результата и завершение future
```

Для каждого вызова создаётся новая `Session`, содержащая текущие значения обратной связи `feedback` и счётчика `counter`. Между порциями одной операции они сохраняются; между разными вызовами не переносятся. Каждый новый вызов начинает с исходного IV. Поэтому два вызова шифрования частей массива не эквивалентны одному вызову для целого массива.

`Settings` хранит алгоритм и настройки. Фоновые задачи удерживают их через `std::shared_ptr`, поэтому могут завершиться после уничтожения объекта контекста.

## 4. Набивка и размер результата

Набивка добавляется один раз в конце всего сообщения, а не после каждого блока или каждой прочитанной порции. В этой реализации она применяется во всех режимах, включая CTR, CFB и OFB; значения «без набивки» в перечислении нет.

Пусть `B` — размер блока в байтах, `N` — длина входа. Для PKCS7, ANSI X.923 и ISO 10126 добавляется `k = B - (N % B)` байтов, где `1 <= k <= B`. Для Zeros добавляется `(B - N % B) % B` байтов.

| Набивка | Добавляемые байты при `k = 3` | Удаление |
|---|---|---|
| `Zeros` | `00 00 00` | По исходной длине `OriginalSize`, с проверкой удаляемых нулей |
| `AnsiX923` | `00 00 03` | Последний байт задаёт длину, предыдущие байты набивки проверяются на ноль |
| `PKCS7` | `03 03 03` | Последний байт задаёт длину, все байты набивки должны ей соответствовать |
| `Iso10126` | Например, `A7 4C 03` | Последний байт задаёт длину, случайные байты не проверяются |

В ISO 10126 случайные байты получаются через `std::random_device`.

Примеры для DES и PKCS7:

| Исходная длина | Добавляется | Длина шифротекста |
|---:|---:|---:|
| 0 байтов | 8 байтов `08` | 8 байтов |
| 5 байтов | 3 байта `03` | 8 байтов |
| 8 байтов | 8 байтов `08` | 16 байтов |
| 10 байтов | 6 байтов `06` | 16 байтов |

При исходных 8 байтах первый блок содержит данные, второй — только набивку; оба блока шифруются. Сам DES размер одного блока не увеличивает.

Для Zeros пустой вход остаётся пустым, а выровненный вход не расширяется. Для дешифрования обязательно передать `crypto::OriginalSize{N}` в конструктор: настоящие нули в конце данных невозможно отличить от набивки без длины. Этот параметр хранится в контексте, поэтому для сообщений разной длины при Zeros нужны контексты с соответствующими значениями. Для остальных набивок `OriginalSize` не используется и не проверяет длину результата.

## 5. Режимы шифрования

Обозначения: `P_i` — открытый блок, `C_i` — шифроблок, `E` и `D` — шифрование и дешифрование одного блока установленным ключом, `XOR` — побитовое исключающее ИЛИ. Нумерация блоков начинается с нуля.

| Режим | Шифрование | Дешифрование |
|---|---|---|
| ECB | `C_i = E(P_i)` | `P_i = D(C_i)` |
| CBC | `C_i = E(P_i XOR F_i)`, затем `F_next = C_i` | `P_i = D(C_i) XOR F_i`, затем `F_next = C_i` |
| PCBC | `C_i = E(P_i XOR F_i)` | `P_i = D(C_i) XOR F_i` |
| CFB | `C_i = P_i XOR E(F_i)`, затем `F_next = C_i` | `P_i = C_i XOR E(F_i)`, затем `F_next = C_i` |
| OFB | `G_i = E(F_i)`, `C_i = P_i XOR G_i`, затем `F_next = G_i` | Та же генерация гаммы, `P_i = C_i XOR G_i` |
| CTR | `C_i = P_i XOR E(T_i)` | `P_i = C_i XOR E(T_i)` |
| RandomDelta | `C_i = E(P_i XOR T_i)` | `P_i = D(C_i) XOR T_i` |

Для CBC, PCBC, CFB и OFB начальное `F_0 = IV`; в PCBC после каждого блока `F_next = P_i XOR C_i`. CFB использует обратную связь размером в полный блок.

Для CTR `T_0 = IV`, `T_next = T_i + 1`. Для RandomDelta `T_0 = IV`, `T_next = T_i + Delta`. Сложение в `add` выполняется в big-endian по модулю `2^(8 * B)`, с переносом между байтами и отбрасыванием конечного переполнения. Повторение счётчика после полного цикла реализация не отслеживает.

Формула RandomDelta выше — явно выбранный вариант реализации: в задании точная схема не приведена. Контекст не добавляет заголовок RD и не шифрует IV отдельным блоком. Если в материалах курса задан другой формат, потребуется согласовать его с этой реализацией.

## 6. Дополнительные аргументы

| Аргумент | Назначение и ограничения |
|---|---|
| `crypto::WorkerCount{4}` | До четырёх фоновых задач обработки блоков на порцию; допустимо 1–64 |
| `crypto::OriginalSize{5}` | Длина исходных данных в байтах для удаления Zeros |
| `crypto::Delta{{0,0,0,0,0,0,0,3}}` | Шаг RandomDelta для DES: ровно 8 байтов, нечётное big-endian значение |

По умолчанию число задач равно числу аппаратных потоков, ограниченному диапазоном 1–8. Фактическое число задач не превышает числа блоков в порции. `Delta` обязательна для RandomDelta и запрещена для других режимов; случайные IV и Delta подготавливает вызывающий код. Повтор одного типа дополнительного аргумента вызывает исключение.

## 7. Асинхронность и параллельность

Каждый публичный метод запускает задачу через `std::async(std::launch::async)` и возвращает `std::future`. Асинхронность позволяет продолжить работу вызывающего кода, а параллельность внутри операции распределяет независимые блоки между задачами.

| Режим | Параллельное шифрование | Параллельное дешифрование |
|---|---|---|
| ECB | Да | Да |
| CBC | Нет | Да |
| PCBC | Нет | Нет |
| CFB | Нет | Да |
| OFB | Нет | Нет |
| CTR | Да | Да |
| RandomDelta | Да | Да |

`future.get()` ждёт завершения, возвращает результат и передаёт исключение фоновой задачи; его можно вызвать один раз для данного future. Немедленный `.get()` делает вызывающий код ожидающим, хотя операция выполняется в фоне. Сохраните future, если хотите выполнить другую работу до ожидания. Уничтожение последнего future от `std::async` до завершения задачи также может ожидать её окончания; отмена операций не предусмотрена.

Алгоритм `IBlockCipher` должен поддерживать одновременные вызовы `encryptBlock` и `decryptBlock` после установки ключа. У DES промежуточные данные локальны; изменение ключа одновременно с обработкой блоков недопустимо.

## 8. Перегрузки для массивов

| Вызов | Результат |
|---|---|
| `encryptAsync(input)` | `std::future<Bytes>` с шифротекстом |
| `decryptAsync(input)` | `std::future<Bytes>` с восстановленными данными |
| `encryptAsync(input, output)` | `std::future<void>`, запись в `output` |
| `decryptAsync(input, output)` | `std::future<void>`, запись в `output` |

`Bytes` — это `std::vector<std::uint8_t>`. Вход принимается по значению: обычная переменная копируется, а переданная через `std::move` перемещается в задачу. Выходной массив, переданный по ссылке, должен существовать и не читаться и не изменяться другими потоками до завершения операции. Его значение заменяется только после успешной обработки всего массива.

Внутри `process` входной массив преобразуется в строку и поток в памяти, затем обрабатывается общей функцией `processStream`. Поэтому при обработке массива возникают дополнительные копии данных в памяти.

## 9. Обработка файлов

```cpp
context.encryptAsync(std::filesystem::path("input.bin"),
    std::filesystem::path("encrypted.bin")).get();
context.decryptAsync(std::filesystem::path("encrypted.bin"),
    std::filesystem::path("restored.bin")).get();
```

Обе перегрузки возвращают `std::future<void>`. Файлы открываются в бинарном режиме и читаются порциями по `1024 * B` байтов: для DES это 8192 байта. Содержимое файла целиком в память не загружается.

1. `processFile` проверяет, что вход и выход не ссылаются на один файл, и открывает потоки.
2. `processStream` создаёт Session и читает порцию.
3. По EOF или проверке следующего символа определяет последнюю порцию.
4. При шифровании добавляет набивку только к последней порции и преобразует блоки.
5. При дешифровании проверяет кратность размеру блока, преобразует блоки и удаляет набивку только из последней порции.
6. Записывает результат, сохраняя состояние режима для следующей порции.
7. После завершения файловой операции сбрасывает буфер записи и проверяет состояние потока.

Если последняя прочитанная порция уже выровнена, PKCS7, ANSI X.923 и ISO 10126 добавляют к ней полный блок набивки: для DES последняя порция может вырасти с 8192 до 8200 байтов. При удалении Zeros учитывается число байтов, уже записанных из предыдущих порций.

Существующий выходной файл перезаписывается. Если ошибка возникла после начала записи, он может остаться пустым или содержать частичный результат; автоматического отката нет. Родительскую папку выходного файла нужно создать заранее.

## 10. Настройки для дешифрования и ошибки

Для восстановления используйте тот же алгоритм, ключ, режим, набивку, IV и, для RandomDelta, Delta. Для Zeros дополнительно нужна точная исходная длина. Контекст не записывает эти параметры в массив или файл: хранить и передавать их нужно отдельно.

Ошибки конструктора возникают синхронно. Ошибки обработки данных и файлов передаются через `future.get()`.

| Ситуация | Результат |
|---|---|
| Пустой указатель алгоритма, неизвестное значение перечисления, неверный IV или аргументы | `std::invalid_argument` |
| Неверная длина ключа | Исключение реализации алгоритма, у DES — `std::invalid_argument` |
| Шифротекст не кратен размеру блока, некорректная набивка, нет OriginalSize для Zeros | `std::invalid_argument` |
| Входной и выходной файлы совпадают | `std::invalid_argument` |
| Ошибка открытия, чтения, записи или сброса буфера файла; неверный размер блока, возвращённого алгоритмом | `std::runtime_error` |
| Ошибка операции файловой системы при проверке путей | Возможно `std::filesystem::filesystem_error` |

Проверка набивки обнаруживает лишь часть повреждений: корректная набивка сама по себе не подтверждает правильность ключа или подлинность данных.

Для нового независимого сообщения задавайте новый IV согласно выбранному режиму; в ECB IV отсутствует. Использование одного контекста повторно автоматически IV не меняет.
